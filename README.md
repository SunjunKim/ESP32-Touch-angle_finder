# Axicube Replica 0.0.2 — ESP32-S3 Touch LCD 1.69

Waveshare ESP32-S3-Touch-LCD-1.69용 각도계 펌웨어. 현재 REL은 가속도계만
사용하며, 자이로 적분·정지 대기·추적 손실 상태를 사용하지 않는다.
제품 코드 정리 기준일: 2026-09-08. 정밀도 인증 또는 실기 검증 완료 선언은 아니다.

## REL 사용법

1. 칼면과 스톤면 중 더 수평에 가까운 기준면에 기기를 밀착한다.
2. 기존 영점 버튼을 3초 누르고, 안내에 따라 손을 뗀다.
3. 영점 순간 중력 성분이 가장 큰 X/Y/Z축을 접촉면 법선으로 고정한다.
   `N:X/Y/Z locked`를 확인한다. 측정 중에는 자동으로 축을 바꾸지 않는다.
4. 같은 기기 접촉면으로 대상면에 부착하여 상대각을 읽는다.
   기준면 자체를 움직였거나 기기의 접촉면을 바꿨다면 다시 영점을 잡는다.

표시는 0–90°의 무부호 상대각이며 0.1° 단위다. 이동 중에도 계속 표시한다.
빨강은 움직임/필터 안정화 힌트, 하양은 안정화 힌트일 뿐 정확도 보증이 아니다.
유효한 센서 데이터가 500ms 이상 없으면 `--`로 표시한다. 출력 필터 시정수는
0.15초다. 상세 수식과 이력은 [ACCEL_REL.md](ACCEL_REL.md)를 참조한다.

완전 수평 영점 및 정렬된 단축 회전에서는 이상적인 기하값을 얻는다.
기울어진 기준면에서 상대 방위가 바뀌면 가속도계만으로 복원할 수 없는
각도 오차 및 부호 분기 경계가 남는다. 움직임 중 병진 가속도, 센서 편향,
케이스와 연마면의 비평행도도 오차 원인이다. 표시 분해능은 측정 정확도가 아니다.

## 캘리브레이션

6방향 CAL 순서는 유지하며, LCD facing up 측정을 수평 기준으로 사용한다.
Facing up은 수평이고 평탄한 면에 놓는다. Facing down은 조립 구조 때문에
기울어져도 되며, up의 정확한 반대 벡터라고 가정하지 않는다. 여섯 측정값 모두
보정 후 크기가 1g가 되도록 오프셋과 축별 스케일을 계산하고, up과 측면 쌍으로
장착 회전을 정한다. Down의 방향 검사는 잘못된 면을 거르는 용도이며 nominal
방향에서 60도 미만까지 허용한다. 다른 면은 기존 방향 기준을 유지한다.
기존 저장값은 계속 읽을 수 있지만 새 방식을 적용하려면 CAL을 다시 수행한다.
각 면을 올바른 방향으로 놓은 뒤 2초간 정지 상태가 확인되면 계측을 시작하고,
이후 3초간의 가속도 샘플 평균을 해당 면의 보정값으로 사용한다. 계측 중 움직이면
그 면의 정지 확인과 계측을 다시 시작한다.
REL 영점과 센서 캘리브레이션은 별개다. 기존 NVS 키와 진단 펌웨어의
`data_v3` 레코드 읽기 호환성을 유지한다. 새 보정은 `data_v3` 단일 레코드로만
저장하며, 쓰기 결과와 저장소를 다시 열어 읽은 값이 일치해야 메모리에 적용하고
완료를 표시한다. 실패 시 사용 중인 보정값은 유지하고 재시도를 안내한다.
기존 개별 키는 읽기 전용으로 유지한다. CAL 진입 후 REL 영점은 다시 잡는다.
CAL 단계·샘플 누적·보정 적용은 IMU 태스크가 전담하고, 화면 터치는 시작 요청만 전달한다.
이번 5개 면 진단의 추정 보정값은 적용하지 않았다. USB 쪽 한 면이 빠진
진단을 완전한 6면 캘리브레이션으로 간주하지 않는다.

## 빌드

Arduino CLI와 ESP32 보드 패키지, Arduino_GFX_Library, lvgl, SensorLib 및
프로젝트가 사용하는 주변장치 의존성이 필요하다. 로컬 `lv_conf.h`를 사용한다.
라이브러리 내부 파일은 변경하지 않는다. LVGL 8/9 분기를 제공하지만 이번
검증은 설치된 라이브러리 조합에 한정된다.

0.0.2 빌드 환경: Arduino CLI 1.5.1, ESP32 core 3.3.11, LVGL 9.5.0,
GFX Library for Arduino 1.6.7, SensorLib 0.4.1,
Driver Bus Library Based on Arduino 1.0.1, 로컬 Mylibrary(버전 메타데이터 없음).
Mylibrary 등 외부 의존성은 이 저장소에 포함되어 있지 않아 별도 설치가 필요하다.

```sh
arduino-cli compile \
  --fqbn esp32:esp32:waveshare_esp32_s3_touch_lcd_169:PartitionScheme=app3M_fat9M_16MB,PSRAM=disabled \
  --build-path /private/tmp/axicube-production .
bash tests/run_host_tests.sh
```

반복 USB 진단은 기본 OFF다. 필요할 때 컴파일 옵션
`--build-property build.extra_flags=-DAXICUBE_REL_DIAGNOSTICS=1`을 추가한다.
진단 빌드는 115200 baud로 `REL_CONTACT`를 최대 초당 한 번 비차단 출력한다.
`python3 simulation/capture_serial.py --port /dev/cu.usbmodem… --duration 60`으로
수집한다. 기존 로그처럼 초기 버퍼 데이터가 포함될 수 있으므로 분석에서 제외한다.
업로드는 별도로 수행하며 보정값 초기화/전체 플래시 삭제는 하지 않는다.

## 검증 및 개발 기록

- 활성 REL 회귀: `tests/contact_rel_test.cpp`의 중앙 23,808 자세와
  18,360 장착면 등가성 표본. 후자는 임의 방위에서 실제 각도 정확도 검증이 아니다.
- 실측 45° 지그 표시: 두 장착 조건에서 46.7° / 45.8°; 복귀 0.0–0.1°.
  지그 자체 정밀도는 확인하지 않았으므로 제품 정확도 수치로 사용하지 않는다.
- [5개 면 진단](simulation/hardware_logs/FIVE_FACE_CONTACT_DIAGNOSTIC_20260907.md):
  방향 의존 편차, 접촉 상태 및 잔여 편향 가능성. 보정값 미적용.
- `simulation/`과 그 안의 `experimental/`은 개발 기록과 폐기 후보를 보관한다.
  자이로 추적기는 제품 펌웨어에 포함되지 않는다.
- `STATIONARY_REL.md`, `IMU_TUNING.md`, `HARDWARE_TEST.md`,
  `SIMULATION_FINDINGS.md`는 과거 조건에 대한 기록이다. 현재 사용법은 본 문서가 우선한다.

남은 실기 확인: production 빌드의 화면·터치·영점, 재부팅 후 기존 CAL 로드,
장착면별 수평/45° 왕복과 좌우 회전 반복. 이 정리 작업에서는 재업로드하지 않는다.

## 배터리 표시

숫자는 평활화된 배터리 전압만 소수 둘째 자리까지 표시한다(예: `3.85V`).
아이콘의 채움 레벨은 정격 3.7V / 만충 4.2V 단셀 리튬폴리머(Li-Po)의 비선형 전압 룩업 테이블을
선형 보간한 추정 잔량을 표시한다. 3.50V=0%, 3.70V=10%, 3.85V=50%,
4.00V=80%, 4.10V=90%, 4.20V=100%다. 0%는 기존 3.5V 종료 기준에
맞춘 기기 사용 가능 잔량이며, 셀의 화학적 완전 방전을 뜻하지 않는다.
기존 ADC 환산 계수와 전압 평활화(1초 주기, alpha=0.15)는 유지한다.

이 테이블은 일반적인 곡선의 근사값이며 특정 셀의 실측 데이터나 공인된
범용 SOC 함수가 아니다. 충전/방전 모두 전압에 따라 갱신하되, 충전 전류에
의한 전압 상승은 아래의 고정 보정값으로만 근사하며 부하·온도·노화 오차를
정확히 보정할 수 없다. 100%도 충전 완료
신호가 아니다. 정확도를 높이려면 사용 셀과 부하에서 전압–용량을 측정해
`src/battery_soc.h`를 보정하거나 전류 측정 가능한 fuel gauge를 추가한다.
방법과 한계: [TI 전압 기반 SOC 추정](https://www.ti.com/lit/an/sluaaa1/sluaaa1.pdf).

동봉 회로도 V2.1의 U9 ETA6098 STAT(9번 핀)은 미연결이다. 데이터시트에
따르면 충전 중 LOW, 완료 시 high-impedance지만 MCU에서 읽을 수 없다.
정확한 충전 상태 감지에는 STAT를 MCU의 사용 가능한 GPIO에 적절한
3.3V 풀업과 함께 연결하는 하드웨어 변경이 필요하다.

현재는 전압 변화로 plug/unplug를 추정하는 휴리스틱을 적용한다.
USB 호스트 연결(`HWCDC::isPlugged()`) 또는 전압 기반 연결 추정 시
배터리 내부에 투명 배경의 흰색 번개를 겹쳐 표시한다.
충전 표시 중에는 채움색을 짙은 청록색, 테두리와 단자를 민트색으로 바꾼다. 두 조건 모두 없으면 숨긴다.
USB 호스트 감지는 시리얼 모니터를 열지 않아도 동작하며 약 1초마다 갱신한다.
충전기·보조배터리·충전 전용 케이블 및 USB suspend 상태는 이 방식으로
확인할 수 없어 전압 휴리스틱을 사용한다. USB 감지는 아이콘에만 적용하고
SOC 곡선 선택은 기존 전압 추정 상태를 유지한다.
이 표시는 외부 전원 연결 추정이며 실제 충전 여부/완료를 뜻하지 않는다.
- 1초 간격 원전압에 3샘플 중앙값 필터를 적용한다(SOC용 EMA와 별도).
- 직전 8개 필터값의 범위가 40mV 이내일 때만 그 평균을 기준으로 삼는다.
- +20mV 이상 상승은 연결 후보, -20mV 이하 하락은 분리 후보다.
- 후보 발생 후 변화량의 75% 이상이 3초간 유지되어야 상태를 확정한다.
- 급변 확정 뒤 5초간 재감지를 억제한다.
- 완만한 변화는 최근 30개 필터값의 앞 10개와 뒤 10개의 절사평균을 비교한다.
  각 구간에서 큰 값/작은 값 2개씩을 제외한다. 평균 차이가 +4mV면 연결,
  -4mV면 분리 방향이며 3회 연속 확인되면 상태에 반영한다(약 30초 이상 필요).
- 변화가 잡음 범위 안이면 마지막 상태를 유지한다. 상태 변경 시 추세 창을
  초기화해 이전 연결/분리 전압 변화가 반대 방향으로 재해석되는 것을 줄인다.
- 시작 상태는 미확인(오버레이 없음)이다. 처음부터 USB가 연결되어 있으면
  판별하지 못한다. 2.5초 초과 샘플 공백이나 비정상 전압은 미확인으로 초기화한다.

임계값은 실기 튜닝 전의 초기값이며 `src/battery_plug.h`에서 조정한다.
지속적인 부하 변화는 오검출될 수 있고, 완충 부근의 작은 전압 변화나
5초 이내 재연결은 놓칠 수 있다. 놓친 분리 이벤트는 표시를 남길 수 있다.
휴리스틱은 아이콘과 SOC 곡선 선택에 사용하며 충전 제어·저전압 종료에는 사용하지 않는다.

추정 연결 상태는 충전 곡선, 추정 분리는 방전 곡선을 선택한다. 미확인은
방전 곡선을 초기 기준으로 사용한다. 충전 곡선은 측정 전압에서 80mV를
차감해 기존 테이블에 넣는 초기 모델이다. 충전 전압 상승을 근사할 뿐
실측 보정이나 CC/CV 용량 적산은 아니다. 특히 CV 구간의 실제 SOC를
전압만으로 알 수 없으며, 이 모델은 충전 중 100%를 보장하지 않는다.

충전/방전 각각 마지막 표시 SOC를 RAM에 저장한다. 전환 시 들어갈 상태의
저장값을 나가는 상태의 마지막 SOC에 맞춰 재기준화하고, 새 곡선과의 차이를
오프셋으로 잡아 전환 샘플의 SOC를 그대로 유지한다. 이후 새 곡선을 따라가며
오프셋은 초당 0.02%p씩 0으로 줄이고, 표시 SOC 변화는 초당 최대 0.2%p로 제한한다.
긴 샘플 공백은 2초로 제한해 한 번에 최대 0.4%p만 변한다. 숫자에는 SOC 대신 전압을 표시하고, 이 SOC는 아이콘 채움에만 사용한다. 이력은 재부팅 시 초기화되며, 전압 기반 추정이므로 부하 변화에
따라 충전 중 소폭 감소/방전 중 소폭 증가할 수 있다.

실기 확인: USB 분리/연결 상태에서 전압과 표시 잔량을 비교하고, 100% 및
저전압 구간까지 충·방전하며 실측한다. 이번 변경은 장치에 자동 업로드하지 않는다.
