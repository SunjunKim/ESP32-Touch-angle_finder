# Axicube 사전 컴파일 펌웨어 업데이트

이 폴더를 통째로 배포한다. Arduino IDE/CLI, ESP32 core, 센서·화면 라이브러리나
소스 컴파일이 필요 없다. **Python 3.10 이상**은 설치되어 있어야 한다.
처음 실행할 때 패키지 폴더 안 `.venv`에 esptool 5.1.0과 의존성을 설치하므로
인터넷이 필요하다. 이후 같은 PC/폴더에서 설치가 유지되면 오프라인 업데이트가 가능하다.
운영체제 간에는 `.venv`를 복사하지 말고 ZIP 원본을 새로 압축 해제한다.

1. ZIP을 쓰기 가능한 폴더에 압축 해제한다.
2. 데이터 USB 케이블로 Waveshare ESP32-S3-Touch-LCD-1.69를 연결한다.
   시리얼 모니터를 닫는다.
3. 해당 폴더의 터미널에서 실행한다.

   macOS: `bash flash-macos.command`

   Windows: `.\flash-windows.cmd`

4. 표시된 USB 후보가 본인의 Waveshare 1.69인지 확인하고 `UPDATE`를 입력한다.
   바이너리 체크섬·파티션 검사 → 같은 일련번호 확인 → 다운로드 모드 리셋 →
   플래시 쓰기/검증 → 재부팅 요청 순서다. 진행 중 USB를 분리하지 않는다.
5. 화면 버전과 터치·기존 CAL·영점 기능을 확인한다. 스크립트는 앱 부팅을 확인하지 않는다.

옵션: `--list` 탐색만, `--dry-run` 검사/계획만, `--port COM8` 포트 선택,
`--serial USB일련번호` 특정 기기, `--yes` 확인 생략.
래퍼는 `--dry-run`에서도 처음에는 도구 설치를 할 수 있으나 장치를 리셋/쓰기하지 않는다.

USB ID는 여러 ESP32 제품이 공유하므로 모델의 증명이 아니다. 여러 후보가 있으면
선택 없이 중단한다. 다른 모델에는 사용하지 않는다. 체크섬은 파일 손상 검출용으로,
배포자 인증/디지털 서명이 아니므로 신뢰하는 ZIP만 사용한다.

바이너리를 합치지 않고 4개 구간만 쓴다. NVS `0x9000–0xDFFF`를 건드리지 않아
현재 프로젝트와 같은 파티션 배치의 CAL 데이터를 유지한다. 전체 삭제를 하지 않는다.
다른 파티션 구성의 제품에서 데이터 이행을 보장하지 않는다.

자동 리셋 실패 시 BOOT를 누른 채 RESET을 눌렀다 떼고 BOOT를 놓은 후 `--list`로
다시 확인한다. 수동 다운로드 모드에서는 쓰기 후 RESET을 직접 눌러야 할 수 있다.
장치가 아예 열거되지 않으면 케이블/드라이버/장치 상태부터 확인한다.

Windows 실제 플래시 및 이번 패키지의 실기 리셋/업로드는 별도 검증 항목이다.
Python/esptool 설치는 [공식 설명](https://docs.espressif.com/projects/esptool/en/latest/esp32/installation.html)을 참조한다.
