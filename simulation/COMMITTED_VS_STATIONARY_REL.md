# 最新커밋 2f9d288 vs 현재 정지 REL

비교 실행: `clang++ -std=c++17 -O2 -Wall -Wextra -Werror tests/compare_committed_rel.cpp -o /private/tmp/compare-committed-rel && /private/tmp/compare-committed-rel`.

구형은 HEAD `2f9d288`의 `rel_update_angle_sample` 수식을 그대로 이식했다. 가속도 X에서 pitch 부호를 정하고 전체 기울기의 부호를 붙인 뒤 저장한 ref_angle을 뺀다. 최초 기준 저장 전 0.15° deadband도 재현한다. 앱 가속도는 수평 −Z이므로 시뮬레이션의 up과 부호가 반대다. 구형 표시가 음수인 경우 방향 부호 자체를 오차로 세지 않고 `abs(표시값)−실제 예각`으로 비교했다. 구형 펌웨어의 전체 스케줄러나 UI 반올림은 실행하지 않았다.

신형은 실제 `src/pages/stationary_rel_tracker.h` C++ 코드를 실행한다. 이상적인 상태 추적을 정답으로 대체하지 않는다. 참값은 독립적인 칼/스톤 법선 기하에서 계산한다.

조건: 최신 합성 200mm 칼(중앙 55%까지 직선, 이후 2차 곡선), 중앙 칼면 1회 기준, 피벗 X/Y 고정·높이 58.5mm, β=0/−3/−8/−15°. 신형은 중앙 스톤 방향 확인을 추가 수행한다. 각 목적지마다 초기화/기준 설정 후 중앙에서 2초 동안 목적지로 이동하고 3초 정지한다. 즉 이 결과는 장시간 재확인 없는 연속 작업을 보장하지 않는다. 입력 주기는 10ms이다.

## 로그 규모의 합성 바이어스/잡음

모드1: 자이로 바이어스가 초당 (−0.0081,−0.000503,+0.000199)°/s씩 선형 변화하도록 가정. 나머지 센서는 이상적이다. 신형 최대 오차는 모든 β에서 0.0001° 미만. 구형은 자이로를 쓰지 않아 변하지 않는다. 바이어스 변화가 보간 모델과 일치하는 유리한 조건이라는 점을 주의한다.

모드2: 위 변화에 독립 Gaussian 가속도 잡음 σ=(0.000389,0.000546,0.000368)g, 자이로 잡음 σ=(0.0291,0.0343,0.0279)°/s 추가. 규모는 기록한 로그에서 가져왔지만 원래 잡음의 시간 상관/온도 비선형성/실제 장착오차는 재현하지 않았다. 21개 위치×10개 고정 난수 시드, β별 210회.

| β | 구형 최대 절대 오차(전체 210회) | 신형 최대 절대 오차(유효 출력만) |
|---|---:|---:|
| 0° | 0.064810° | 0.007359° |
| −3° | 1.161890° | 0.009130° |
| −8° | 3.471809° | 0.009003° |
| −15° | 7.488796° | 0.009350° |

신형은 β별 201/210회(95.7%)에서 3초 정지 후 유효 출력, 나머지 9회는 Settling 상태로 값을 숨겼다. 실패를 0오차로 계산하지 않았다. 양측 비교 표는 각 알고리즘의 출력 정책까지 반영하므로 신형의 더 긴 대기시간이라는 비용도 고려해야 한다. 이 표를 실물 ±0.01° 정확도 주장에 사용하면 안 된다.

결론: 경사진 칼면의 곡선 구간에서는 구형의 지배적인 오차가 기하 계산 자체에 있다. 신형은 그 오차를 제거하는 대신 이동 중 자이로 연속성, 중앙 방향 확인, 정지 대기시간을 필요로 한다. 칼면이 수평이면 구형도 이상 조건에서 정확하다. 실제 가속도 절대 캘리브레이션 오차/중앙 정렬 오차/장착 오차/자이로 scale error와 비선형 drift는 여전히 실기 검증 대상이다.
